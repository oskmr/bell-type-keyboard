# commit-pr

このスキルは、現在の差分をレビューしやすい単位に整理してコミットし、そのまま PR を作成するための手順です。

## 使う場面

- 変更をコミットして PR まで作りたい時
- ひとまとまりの差分を適切な粒度に分けたい時
- 既存の作業ブランチを GitHub 上に出したい時

## 基本方針

- 既存の意図と無関係な変更は入れない
- 1 つのコミットは 1 つの論理変更にまとめる
- 必要ならコミットは複数に分ける
- 既に開いている PR があれば、原則としてそれを更新する
- `gh` が使える前提で、最後まで自動で実行する

## 実行手順

1. `git status` と `git diff` を確認し、変更を論理単位に分ける
2. 変更が 1 つの目的にまとまるなら 1 コミット、まとまらないなら複数コミットに分ける
3. それぞれのコミットについて、必要なファイルだけを stage する
4. 意味のある commit message を付けて `git commit` する
5. `git push -u origin <branch>` でブランチを push する
6. `gh pr create` で PR を作成する
7. 既存 PR がある場合は、新規作成ではなく内容を更新する

## コミットの粒度

- 機能追加、修正、リファクタリングは分けられるなら分ける
- 1 コミットに複数の独立した修正を混ぜない
- ただし、レビュー上明確に一体であるなら無理に分割しない
- 迷う場合は、将来のレビューで理解しやすい分割を優先する

## commit message

- 先頭で変更内容が分かる短いメッセージにする
- 命令形または簡潔な現在形で書く
- 例: `Fix keyboard preview update`、`Add commit-pr skill`

## PR 作成

- PR タイトルはコミット群の要約にする
- PR 本文には以下を簡潔に含める
- 何を変えたか
- なぜ必要か
- テストや確認内容
- 影響がある場合は補足

- `gh pr create --fill` を起点にしつつ、必要なら本文を上書きする
- PR が既にある場合は、`gh pr view` で確認してから更新する

## 失敗時の扱い

- `gh` 未ログインなら、その時点で止めてログイン状態を確認する
- push できないなら、原因を特定してから続行する
- 予期しない差分が見つかったら、勝手に消さずに報告する
